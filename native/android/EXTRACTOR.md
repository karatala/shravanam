# Packaged YouTube extractor

`player/src/main/res/raw/shravanam_ytdlp.zip` is the unmodified official [yt-dlp 2026.10.26 zipimport distribution](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.10.26). Its release SHA-256 is `e51e69e89489f199530f13d32a4342da3ddb2cf34842f364603a066db05afbf3`. `shravanam_extractor.json` pins the version, source URL, checksum, and included EJS 0.8.0. License texts and a notice are packaged under `assets/licenses`.

youtubedl-android 0.18.1 still owns Python, QuickJS, process execution, and FFmpeg. Its default extractor was 2025.11.12 and used the removed `android_sdkless` client. Upstream [removed that client to address 403 failures](https://github.com/yt-dlp/yt-dlp/commit/309b03f). The app pins the extractor separately so an APK update can refresh this code without fetching executable components during playback.

`YouTubeRuntime.initialize` first initializes the library, then verifies its installed `noBackupFilesDir/youtubedl-android/yt-dlp/yt-dlp` against the APK manifest. It atomically replaces an old or different copy only with the checksum-verified packaged resource. All extraction and download entry points use this owner. Positions, recents, and offline media live separately and are retained. The process verifies once; APK installation starts a fresh process. The diagnostic header reports the APK extractor and EJS versions instead of the library's updater preference.

Prefer `visionos` for recorded YouTube requests. Repeated host checks of `vejUfsSFYaM` returned 200 for its initial request and 206 for ranges near the saved position and file end; the default TV client returned 403 and `web_embedded` was intermittent. If visionOS extraction or its stream probes fail, try `web_embedded` once. Streaming checks at most three candidates per client, six in total. Downloads can change clients only before any before-download/progress marker; never restart a partial transfer automatically after a media failure. Keep the existing cancellation and selection guards and the streaming 60-second deadline.

`YouTubeHttp` shares the Media3 HTTP factory and headers between probing, audio, and video. A probe opens the same initial open-ended request as the player, reads one byte into memory, then closes. A `bytes=0-0`-only test can accept a URL which fails actual playback. Log response status, byte position, and requested length, without URLs, headers, or bodies.

To update, select a fixed official release, download its `yt-dlp` asset, verify the release checksum, replace the resource without modifying its shebang/ZIP bytes, and update the manifest and notices together. Run `bun test tests/android-extractor.test.js tests/android-prepare.test.js`. Native runtime installation and HTTP tests run through `:shravanam-player:testDebugUnitTest`. Verify QuickJS extraction, initial playback, nonzero saved-position seeks, video, downloads, and APK upgrade on a device before declaring runtime support. Do not use `latest` downloads or the library updater in the application.
