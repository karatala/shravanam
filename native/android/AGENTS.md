# Android Playback

## Purpose

- Own the versioned Android library and app overlay for native local/YouTube playback and source browsing behind Capacitor.

## Ownership

- `player/` is an Android library with Media3, the playback service, and the Capacitor plugin.
- `PlaybackService.java` owns playback, persistence, the Media3 notification channel and metadata, system time-jump commands, and pending playback intent. `MediaFile.java` validates granted files and reads provider metadata. `ShravanamPlayerPlugin.java` owns the controller binding, picker, and incoming-intent queue.
- `SavedPlayback.java` selects the exact last persisted descriptor, position, actual read grant, and accepted wake keys. `ResumeMediaButtonReceiver.java` uses Media3's receiver flow to restart on Play, Play/Pause, or Headset Hook and reports blocked startup. The service owns resumption callbacks, logical loading metadata, and the initial foreground-notification bridge.
- `YouTubeSource.java` validates individual HTTPS YouTube links and explicit timestamps. `YouTubeResolver.java` uses the pinned youtubedl-android 0.18.1 runtime to resolve audio or video streams and bounded headers. Media3 remains the playback engine.
- `YouTubeRuntime.java` owns the APK-pinned yt-dlp/EJS resource, manifest, checksum verification, atomic refresh of an old library copy, and shared preferred client. `YouTubeHttp.java` owns the common Media3 HTTP factory, open-ended one-byte-read probes, and safe byte-range diagnostics. `EXTRACTOR.md` owns provenance and updates; APK license assets accompany the unchanged upstream archive.
- `OfflineDownloads.java` owns the atomic private download index and checked local copies. `DownloadProtocol.java` owns formats, structured progress, and output-path checks. `DownloadService.java` owns one manual foreground transfer, packaged FFmpeg processing, cancellation, and final Media3 track validation.
- `NativeVideoActivity.java` and `player/src/main/res/layout/shravanam_video.xml` own the private video screen. `VideoSync.java` decides secondary-renderer seeks, frame visibility, and play state from the service audio clock.
- `SourceBrowserActivity.java` owns the private website WebView and native toolbar. `SourceBrowserUrl.java` validates HTTPS addresses and search input. `PlaybackConnection.java` binds temporary native screens to the service; `NativeControls.java` owns their compact controls and system insets.
- `MainActivity.java` registers the local plugin and selects the debug interface origin before Capacitor creates its bridge.
- `DevelopmentServer.java` owns the debug-only native Server button, settings dialog, and device-local server preference. `DevelopmentServerUrl.java` validates local HTTP origins on port 3001 without DNS lookup.
- `PlaybackDiagnostics.java` owns the debug-only native report, clipboard action, and sanitized Logcat output. `DiagnosticLog.java` owns process-memory history, redaction, and report limits.
- `scripts/prepare-android.js` copies this source into the ignored Android project and generates accepted media types from `src/playback.ts`.

## Local Contracts

- The service constructs the primary audio ExoPlayer and uses the common Player API for authoritative playback state and commands. Only native MediaSource installation needs the ExoPlayer API. Disable video/text tracks. The app WebView only selects files, sends validated commands, and reads snapshots. Releasing any interface controller must not release active playback.
- The plugin and service run in the same application process. Keep service access on the main thread; query file providers on the service's serial worker.
- Accept granted content URIs from the system document picker, Open With, and media sharing. Do not expose arbitrary URI or path opening to JavaScript. Attempt persistent read access only when the sender grants it; report temporary access in item metadata.
- No broad storage permission, copying of provider media, arbitrary media URL opening, or automatic downloads. Streaming uses native extraction with no media download or disk cache. Explicit recorded YouTube downloads use a separate app-private offline directory. Share/Open With for links, live streams, and scripts remain separate work.
- Watch opens a second, video-only ExoPlayer with audio/text disabled and audio focus disabled. It follows the service clock without seeking, pausing, or replacing audio to synchronize. Hide the TextureView until a frame is decoded near the audio position; hold video that is ahead and seek video that is behind. Playback controls affect the primary session. Release the secondary decoder, resolver, and controller when the screen pauses; rebuild video at the current audio position on return. Listen closes the video screen and leaves audio running.
- Video extraction uses a separate cancellable worker with a 60-second limit, generation guards, a 1080p maximum, and H.264 preference. Keep only the app-owned media ID in video intents. Service revision/owner tokens prevent old screen cleanup and errors from overwriting a newer request. Video failures remain separate from audio failures.
- The source browser is a plain WebView, never a Capacitor/BridgeActivity, with no JavaScript interface. Keep native controls outside the website. Permit HTTPS navigation only; disable file/content access, mixed content, and new windows. Require WebView MUTE_AUDIO support and mute the page so it cannot produce a second soundtrack; request an Android System WebView update when unavailable. Use a separate website profile when MULTI_PROFILE is supported, avoid the HTTP cache, and destroy the website view on pause. Return reloads the last address without restoring page DOM/history.
- Listen/Watch in the browser validates the actual current YouTube page again and hands its canonical source and selected mode to the service in one command. Destroy the website view and close the browser after playback handoff. Native Download validates the actual page again and offers audio or 480p/720p/1080p; website download callbacks only point to that action. Websites must never receive app file, service, or window bridges.
- Keep 20 canonical YouTube links separately from local recents, with the desktop-compatible YouTube media ID and saved position. Do not put signed stream URLs or headers in preferences, snapshots, archives, or application error logs. Restore the last source paused. Prefer a checked downloaded copy on opening and on system Play; obtain a new stream only when no ready copy is available.
- Keep online and offline playback represented by the same canonical `MediaFile.youtube` descriptor and `position.<id>` key. Store file URIs only in the internal MediaItem, never in recents or interface snapshots. `sourceUrl` is the canonical current YouTube link; `offline` describes the active binding. Explicit offline opening accepts only an indexed ready ID and must not fall back to a network stream. Watch first uses a ready video copy, preferring the selected video variant, and follows the primary audio clock without restarting it. A completed transfer must not replace active playback.
- Download only after a user action from the trusted interface or native browser toolbar. Keep one transfer active and reject a second instead of creating an automatic queue. A separate non-exported `dataSync` service owns its notification, Cancel, wake lock, and six-hour deadline; handle the Android foreground-service timeout and stop foreground state on every exit. Request Android 13+ notification permission in the initiating UI; denial must not prevent a permitted user-started transfer. Use `START_NOT_STICKY`, retain interrupted jobs after process death, and require explicit Retry. Releasing an interface or browser must not cancel a transfer or playback.
- Bundle youtubedl-android FFmpeg 0.18.1 for audio extraction/video merging and Media3 inspector 1.11.1 for track validation. Disable configuration, plugins, remote components, metadata/thumbnail/subtitle files, and caches. Each job uses a canonical YouTube URL and a fixed app-owned output template. Parse only bounded title, progress, and final-file markers; never log raw stdout. Retry obtains fresh extraction and retains `.part` files. Cancellation wins over late completion. Quarantine damaged completed outputs inside their owned directory before retry, without discarding their bytes.
- Keep downloads under `noBackupFilesDir/youtube-downloads`, with an atomic versioned index containing canonical sources, statuses, format, title, byte count, and relative completed filenames. No signed URLs, headers, runtime metadata JSON, media paths, or URI grants in this index or snapshots. Validate canonical directory containment, completed basename, readability/nonzero size, audio/video tracks, and saved byte count before readiness/opening. Incomplete files are never ready. Keep path opening out of JavaScript. Device-local files/index stay outside archives and synchronization; Android library migration remains separate.
- Run extraction on the service's worker, not in the WebView. Bound it to 60 seconds, cancel old work when selection changes or playback stops, and ignore stale completions. Pause/media-key actions during resolution set the requested playback state. A UI reload must not start extraction again. Use stream-specific Media3 HTTP headers, leaving local-file playback unchanged.
- The packaged extractor includes its runtime and QuickJS; do not fetch extractor updates or remote helper components during playback or downloads. App packaging must use extracted native libraries and `useLegacyPackaging = true`. Native features need a new APK; `youtubeSupported`, `videoSupported`, `sourceBrowserSupported`, and `downloadsSupported` in snapshots keep a newer LAN interface from sending unsupported commands to an older APK.
- The APK separately pins yt-dlp 2026.10.26 with its bundled EJS 0.8.0. Initialize both streaming and downloads through `YouTubeRuntime`; verify/atomically refresh the cached executable from the APK so an upgrade does not keep the library's obsolete 2025.11.12 script. Report the packaged versions in diagnostics. Prefer `visionos`, with one `web_embedded` fallback on extraction/probe failure; streaming checks at most three candidates per client, six in total. Downloads must not switch clients after a before-download or progress marker. Keep formats, cancellation, and source identity unchanged; do not use the network updater.
- Disable yt-dlp format checks because they create temporary media files. Check the selected stream and at most five alternatives through the same Media3 HTTP factory as playback. Open the player's initial open-ended request, read only one byte into memory, and close; a bounded `bytes=0-0` request alone does not establish playback access. Keep buffering in RAM, standard Media3 redirect/timeout behavior, and prefer separate audio before a combined stream. HTTP diagnostics contain only status, byte position/length, and method, never URLs or headers.
- Save progress, settings, and 20 recent file descriptors in private SharedPreferences. The active file list lives with the service. Start automatic paused restoration on the first app-interface controller connection, not service creation or system metadata discovery. Revalidate the most recent URI on the serial worker and prepare it at its saved position. Explicit selections invalidate pending automatic restoration. Keep inaccessible recent entries visible and ask for reselection; do not start sound on launch alone. Flush progress on pause, Stop, EOF, and orderly service destruction; retain five-second asynchronous checkpoints for abrupt process death.
- Publish play/pause and time jumps through Media3, including explicit backward/forward button slots and interval icons for supported values. Label the notification channel and source in English/Russian. Publish track title and native timeline; tapping the notification reuses the main Activity without reopening media. Let Media3 handle raw media keys, repeat filtering, and headset gestures. Previous/Next and Rewind/Fast-forward all seek within the current item by the configured intervals; do not switch playlist items or intercept volume keys.
- Finish all `Player.Commands.Builder` additions/removals before `build()`. Media3 consumes this builder on build; build the command snapshot once in each state branch.
- Stop saves position, cancels pending file/YouTube selection, pauses the primary player, and leaves its current item available for Play. Expose ended/failed playback as not ready to play so one headset toggle can replay or retry. Publish pending play intent when no primary audio is available; Pause during file/provider or YouTube work must prevent late autoplay. Explicit new selections may request playback again.
- Keep a service-owned, non-exported audio-becoming-noisy receiver to pause and cancel pending autoplay, including before the first source reaches ExoPlayer. Release it with the service. Player pause/focus-suppression events also cancel pending autoplay; media replacement under `changingMedia` must not cancel the accepted source's own playback request. Keep Media3 audio-focus and normal headphone-disconnect handling enabled.
- A manifest Media3 receiver accepts only the first Play-type key-down for a cold wake. A cold toggle becomes idempotent Play; warm active playback retains normal toggle behavior. Reject cold local resumption without a current persisted read grant. Do not substitute a different recent item when the saved source is missing. Receiver checks must not query a provider or extract YouTube.
- `onPlaybackResumption` returns only app-owned logical media IDs and saved positions. Metadata-only requests do not load media, resolve URLs, or start playback. The session wrapper accepts only the exact saved logical item for resumption; arbitrary URI/playlist mutation stays denied to controllers. Reuse pending startup restoration, and leave newer explicit selections authoritative. A generation check ignores an obsolete queued wake after selection or Stop; Pause before its dispatch cancels it as well.
- Start a silent media foreground notification before asynchronous restoration. Publish loading title/position without a stream URL, expose Play/Pause and Stop, then hand notification ownership to Media3 after native preparation and the playback request. Bound this bridge to 60 seconds; cancel extraction and provider reads, release foreground state, and report an actionable failure on timeout, permission loss, or blocked background startup. A service resumed this way leaves foreground immediately when paused or failed. No Activity, browser, or video screen is opened by headset resumption.
- Pass a `CancellationSignal` through file metadata queries and descriptor opening. Cancel old reads on source changes, Stop, resumption failure, and destruction; retain selection guards for providers that do not stop promptly.
- Keep audio-focus handling, headphone-disconnect pause, and playback wake lock in Media3. Do not release the service when Capacitor pauses or destroys its UI. Device checks must cover actual lock-screen layout, seek controls, headset gestures, and background routing. Android force-stop and system background restrictions remain authoritative; reboot must not autoplay. A post-reboot System UI resumption carousel would need a separate MediaLibraryService contract.
- Use pinned Media3 versions. Do not edit generated Android copies as durable source, and do not run preparation or native builds unless requested.
- Declare Activity, AppCompat, Core, and WebKit directly in `player/build.gradle`: Capacitor keeps its AndroidX dependencies in `implementation`, so they are not on this module's compile classpath. Match root version overrides, with defaults from the pinned Capacitor version. Declare Media3 UI directly for the native video screen. Do not change Capacitor internals to export these dependencies.
- Match the pinned Capacitor Java API: `JSObject.getBool(key)` takes one parameter; `getBoolean(key, defaultValue)` accepts a default. Validate playback boolean types before unboxing.
- Android unit-test compilation also uses the Android API classpath. Use `Files.readAllBytes`/`Files.write` with explicit UTF-8 instead of desktop-only `Files.readString`/`Files.writeString`; Java 21 does not make these helpers available in that classpath.
- Enable server settings only when the installed app has `ApplicationInfo.FLAG_DEBUGGABLE`. Keep the native Server button outside the WebView so recovery still works with an unreachable server or broken interface. Use system-bar/cutout insets for the button.
- Debug APKs expose `diagnosticsSupported` and a narrow `showDiagnostics` plugin method. Opening a report must not bind, start, or change playback. Keep native access under Server when the interface is broken. Record extraction phases, bounded verbose stderr, HTTP probe results, Media3 codes/causes, timeouts, and player state changes. Never record metadata JSON or stream headers. Redact URLs, content/file URIs, paths, and credential lines before both memory storage and Logcat; keep at most 60 events and 48,000 characters in process memory, with no preferences, files, archives, or automatic upload. Copy only the displayed redacted report. Release APKs must not enable verbose extraction or diagnostic access.
- Accept only private/loopback IPv4 or localhost over HTTP on port 3001, with no credentials, path, query, or fragment. Store the chosen origin in private development preferences, outside library data. An empty saved origin explicitly selects bundled assets; it overrides any build-time server URL. Cancel and invalid input must keep the current source.
- Select the origin with a fresh `CapConfig` before bridge creation. Switch by recreating only the Activity; do not pause, stop, or release the playback service. Keep Capacitor bridge access limited to its selected origin. The `player/src/debug/AndroidManifest.xml` overlay allows HTTP only in debug variants; release builds do not get this overlay or the Server button.

## Verification

- `bun test tests/android-extractor.test.js` verifies the exact official archive hash, pinned yt-dlp/EJS versions inside it, solver presence, and removal of `android_sdkless`. `YouTubeRuntimeTest.java` checks cached-extractor replacement, reuse, bad-checksum rollback, and client policy. `YouTubeHttpTest.java` checks open-ended GET/one-byte read and closing a failed source. Host HTTP checks do not establish Android QuickJS, decoder, or seek behavior; keep device checks in `FEATURE_PLAN.md`.
- `DownloadProtocolTest.java` checks structured output, bounded progress, quality limits, and completed/partial/escaped output paths. `OfflineDownloadsTest.java` checks ready-copy identity/selection, atomic restart state, explicit retry, cancellation winning over completion, changed files, and damaged index retention. `SystemControlsTest.java` checks actual offline selection, shared position, and Stop/Play through the real session wrapper with FakePlayer and no resolver. Native execution still needs Android CI; real transfers, FFmpeg, notifications, system limits, and airplane-mode audio/video need device checks.
- `DiagnosticLogTest.java` checks credential/address/path redaction, bounded history and extractor output, exception causes, and circular cause handling. The preparation fixture checks that report sources and this test reach the generated module. APK/device checks still need to confirm copy/refresh, native Server fallback, and the actual YouTube failure.
- Track Android build and device checks separately in `FEATURE_PLAN.md`; source inspection does not establish runtime support.
- `:shravanam-player:testDebugUnitTest` checks native development/browser URLs, video synchronization decisions, and YouTube audio/video stream validation before the CI debug APK build. Preparation fixtures check both private Activities and the TextureView layout. Device checks must cover AV sync, seeks, pause/speed, rotation/background, silent browsing and same-page YouTube handoff, source changes, saved position, stale/cancelled extraction, expired streams, UI reload, and native server recovery. Source/unit checks do not establish real playback continuity.
- `SystemControlsTest.java` injects Media3 FakePlayer directly through Player and exercises the actual session wrapper with Robolectric, without codecs or network. Use `setMediaItems(emptyList)` to empty FakePlayer: its `clearMediaItems` removal handler is not implemented. Attach the service base context and include Android resources for real metadata labels; use Media3's test ControllerInfo factory instead of Mockito. Cover time jumps, Stop/cancel/resume, EOF replay, Pause/headphone removal, metadata-only discovery, and resumption state/provider cancellation. `PlaybackResumeTest.java` checks exact source selection, damaged records/positions, real grant requirements, first key-down filtering, and cold Play. Gradle enables Robolectric's module access for Java 21 and prints full failures. These tests run in the existing CI check and do not establish hardware behavior.
