# Desktop Host

## Purpose

- Runs the shared web application through Bun and the system WebView.
- `scripts/dev-desktop.js` calls the same host with development assets. `runDesktop(assets, { development: true })` enables and opens the app WebView's DevTools, including after tray reopen. Normal desktop launch keeps DevTools disabled.

## Ownership

- `main.js` owns the fixed local server, OS data directory, native window, file dialog, OS drops, and single-instance delivery. `window-state.js` owns local window geometry and maximized-state persistence.
- `browser-host.js` provides the development browser's authenticated control endpoint around the same `media.js` player. `system-file-picker.js` uses OS dialogs without a WebView, following Rachana's picker pattern. `profile.js` resolves native profile locations.
- `chooseMpv` opens a single executable-file dialog and returns `{ path }` or `{ path: null }` on cancellation without changing playback/settings. Native windows use WebviewJS; browser control mode uses authenticated `choose-mpv` with `chooseSystemMpv`, the shared picker guard, and shutdown cancellation. The interface fills its draft and applies it only through `mpv-path`.
- `media.js` owns file intake, recent files, playback actions, EOF playlist transitions, and library/progress boundaries outside the WebView. `library-store.js` owns atomic shared records, local bindings, migration, archives, and one recovery snapshot. `webdav.js` owns manual per-device snapshot synchronization. `sleep.js` owns adaptive timing and saved sleep markers; `speech.js` owns installed OS voices and cancellable speech. `tray.js` owns native menus without a WebView.
- `mpv.js` owns the separate mpv or IINA process, private IPC, audio/video mode, and application-owned mpv configuration.
- `youtube.js` validates and canonicalizes individual YouTube links, finds installed yt-dlp, and resolves HTTPS streams without media downloads. It owns extraction limits and stream/header validation.
- `source-browser.js` owns the separate website window and its trusted local toolbar. `source-scripts.js` owns local userscript validation, persistence, and page preload. `downloads.js` owns manual yt-dlp jobs, partial files, the download index, and offline opening by saved ID.

## Local Contracts

- Use loopback port 47870 and the Shravanam data directory, separate from Rachana. Forward launch files to an existing authenticated instance. Fail for an unrelated port occupant; do not select a new origin.
- Serve only the current asset map. Block external navigation and new windows. Expose window controls, native file selection, playback state, and the validated commands from `src/playback.ts`. Do not expose raw mpv IPC or accept page-supplied media paths. The explicit `mpv-path` setting accepts only an absolute executable-file path or an empty reset value from the trusted app interface.
- Keep the source browser separate from the app WebView. Its toolbar stays on the app origin; external pages use their own persistent `source-browser` context, allow only HTTPS navigation, block new windows, and receive no application bridge or drag helpers. Retain child WebView handles and resize them in logical coordinates. Closing this window disposes its views/context and leaves playback and downloads alive. Retain one hidden empty window until host exit because disposing the last native window also disposes WebviewJS's Application; reuse it when reopening.
- Browser development opens the same native source window on demand. `/__sources` uses the same Host/Origin/token/content-type checks as `/__player` and validates commands from `src/sources.ts`. Import source text, never page-supplied local paths. Website code cannot call the source-control endpoint.
- Userscripts are local page code, not Bun code. Import and the editor support HTTPS `@match`, wildcard schemes restricted to HTTPS, `@exclude-match`/URL-glob `@exclude`, `@name`/`@namespace`, and `@run-at document-start`, `document-end`, or `document-idle`. Execute in the top-level matching website document. Reject privileged `@grant`, remote `@require`/`@resource`, invalid syntax, and files above 128 KiB. Keep up to 32 scripts in `source-scripts.json`, retain its previous copy, and reload the source view after changes. Name/namespace identify updates. Full Violentmonkey APIs are not implemented.
- `downloads.json` contains canonical source links, titles, selected mode/quality, status, and device-local relative filenames. Restore active jobs as interrupted, and retain failed status with its bounded actionable error. Download into private `downloads/<id>/` folders through argument arrays and shared yt-dlp discovery/runtime restrictions. Do not save full extractor metadata or signed stream addresses. Require installed ffmpeg for merging video; never install it automatically. Keep one active manual download, retain partial files for retry, and expose progress/cancel/retry/open without local paths. Mark ready only after successful process exit and a nonempty media file resolves inside the owned directory. Cancellation and shutdown stop only the owned downloader process tree.
- Opening a completed download revalidates its owned path, uses its title and selected mode, and binds its local file identity to the YouTube source progress key. Persist `sourceBindings` in playback.json so startup can restore the local copy paused without network access. This is a native progress association, not shared-library synchronization or backup.
- The local file-forwarding endpoint requires the token from the user's private `open-session.json` and rejects browser Origin headers. Retain batches received before the player is ready.
- Browser development uses port 3000 and the separate `Shravanam-dev` profile to avoid concurrent writes to the packaged desktop profile. Create its player only after the server owns its port. All `/__player` calls require POST, exact loopback Host/Origin, JSON content type, and the per-run token injected into the app HTML. Do not enable CORS, accept page-supplied paths, or expose raw mpv commands. Accept only state, validated playback commands (including `open-youtube`), and system-file selection. Revalidate YouTube URLs in the host before running yt-dlp.
- Reloading, hiding, or closing the development browser must not dispose the Bun player. Terminal shutdown saves progress and closes mpv and a pending file dialog. System dialogs run with argument arrays, never interpolated shell commands. Keep only one picker active.
- Canonicalize and validate native incoming files before registering them. Use the same intake for launch arguments, native file drops, and the file dialog. Add files in order and start the first accepted item.
- `Shravanam/library.json` is the authoritative logical library and progress store. Retain `playback.json` for migration, native recents, local source aliases, audio/video mode, and legacy positions. Migrate once without clearing originals. Use stable device IDs, local counters, deterministic public source IDs, and per-device progress IDs. Keep native paths and bindings outside portable records. Persist every five seconds, on controls and file changes, and before graceful exit.
- Cache the last valid loaded position before engine disconnect and flush it into the library even when the engine is no longer loaded. Clear this cache only after a successful data-replacement flush. Flush errors block archive export, import, restore, and sync boundaries. Reviewed import/sync tokens prevent another window from replacing the user's preview.
- Extract local mpv chapters and recorded YouTube chapter/description metadata when available. Existing edited records stay active. Explicit playlist playback advances once per EOF; ordinary intake and download opening leave the prior queue. Subtitle SRT/VTT parsing and displayed cues live in the shared interface; automatic subtitle retrieval remains pending.
- WebDAV uses one configured HTTPS folder, a separate owned file per device, and conditional ETag writes. Keep conflicting versions and separate device positions. Passwords stay in memory and are never exported. Manual preview/apply is implemented; causal revision ordering, deletion markers, automatic sync, media transfer, and Android adapters remain pending.
- `sleep.json` keeps local timer/speech settings and sleep markers. The host uses active playback time for adaptive signals and a wall-clock response window. Mix labelled brown-noise filters in the same mpv engine; remove only the owned filter. Distinguish automatic gain changes from player-volume responses. Installed system voices run through argument arrays and stdin; cancel pending and active speech on pause, file changes, sleep signals, and exit. Do not speak after the sleep pause or on startup restored paused.
- Clear a storage error only after the replacement settings file is saved successfully. Keep unrelated playback errors intact.
- Retain the latest active-file position in host memory on player updates and save it through the serialized queue when playback stops or the player disconnects. Ignore bootstrap and post-stop properties. Mark media loaded only after position, speed, and pause restoration finish. Play after a stop or disconnect reloads the file at that position, including when duration is not yet available; normal end-of-file replay still starts at zero.
- Keep mpv's `eof-reached` state until it clears or another file loads. While ended, report pause and the full duration even after late position, pause, or duration updates, so completion saves zero and Play starts again at zero.
- Save 20 recent files with canonical paths in the private profile. Expose names and IDs, never paths, through playback snapshots. Revalidate files before reopening. On startup, restore only the last file and leave mpv paused; incoming launch/drop/Open With requests take priority. Missing or changed files remain in recents with an actionable error.
- Find mpv beside the executable, in macOS Resources, on PATH, at standard Homebrew paths, or inside mpv.app in system/user Applications. If mpv is absent or fails during startup on macOS, use IINA.app from system/user Applications. Clear the failed process, socket, and pending commands before fallback; late events must not stop the replacement. Keep IINA selected for later restarts in the same host session. Report a player error only after startup fallback fails. Do not download either player automatically. Bundling remains separate work.
- Do not add package-manager-specific player discovery. Let the user set an executable path in Player settings when automatic search fails. `media.js` validates and stores `mpvPath` only in private `player.json`, exposes it only to the trusted player interface, and excludes it from portable library settings. `mpv.js` uses the configured executable before automatic search, with no fallback for an invalid explicit path. An empty setting restores automatic search. Changes apply on the next engine start; an existing engine keeps running. Report invalid or unavailable configured paths as `player-path` with correction instructions.
- Launch IINA's application executable directly in a separate process with a private IPC socket. Own and stop only that PID; never attach to or terminate the user's existing IINA processes. Open generated silence and wait for it to load before loading user media; an IPC connection alone does not mean IINA has finished opening its launch file. Match each file-loaded event to the requested path before completing a load. Mute during file loading and seeking to the saved position; apply the requested pause state before unmuting. Set the process-local `pauseWhenOpen` preference to `YES` so IINA cannot resume after the host restores pause. The host owns autoplay. Override IINA history, resume, advanced mpv settings, thumbnail, and automatic next-file preferences through launch arguments, without writing user preferences.
- Desktop defaults to Listen (video disabled). Persist `audioOnly` in playback.json and expose the selected backend and mode in snapshots. The validated `audio-only` command switches local tracks without reloading the file. For YouTube, resolve the requested mode again and reload at the current position with the prior pause state. Watch uses a separate player window. IINA requests safe hardware decoding and RAM-only cache limits of 32/8 MiB forward/backward for Listen and 128/32 MiB for Watch. These limits are not total process memory limits. Resource measurements remain pending.
- Create `mpv/mpv.conf` and `mpv/input.conf` only when missing. Standalone mpv uses these files and defaults to RAM caching with 128 MiB forward and 32 MiB backward limits; no media disk cache. IINA uses process-local properties instead of these config files. Input bindings apply to the mpv video window, not global hotkeys.
- Accept only HTTPS YouTube watch, youtu.be, shorts, live-page, and embed video links with an 11-character video ID. Canonicalize to one watch URL; never send page-supplied paths or generic URLs to yt-dlp. Playlist-only links, active/upcoming live streams, authentication, other sites, and offline downloads remain unsupported.
- Run installed yt-dlp with argument arrays, ignored user config/plugins, no remote helper downloads, no disk cache, metadata-only output, a 60-second deadline, and an 8 MiB output limit. On macOS prefer IINA's bundled youtube-dl in system/user Applications. Otherwise search beside the host executable, PATH, and macOS package-manager paths. Enable installed Node/Bun runtimes in addition to yt-dlp's default Deno. Abort extraction on host shutdown. Do not log full metadata or signed stream URLs.
- Listen selects a separate HTTPS audio stream. Watch selects HTTPS video plus audio, with a combined-stream fallback and a preference for 1080p/H.264. Validate googlevideo.com subdomain stream URLs and header values. Pass resolved addresses/headers only to native playback, disable its duplicate yt-dlp extraction, and clear headers for local files. Watch adds the separate audio track while paused, before seeking and playback. RAM-only media caching is enforced for online input.
- Resolver extraction uses yt-dlp `--check-formats` with `--skip-download` to reject inaccessible selected formats before sending them to mpv. A metadata entry alone does not prove that a stream URL is usable. Keep availability checks inside the existing timeout and cancellation boundary; do not write media files during resolution.
- Store up to 20 canonical YouTube links and titles separately from the 20 local recents. Key native progress by a SHA-256 of the YouTube source ID; this is not the shared library record ID. Preserve explicit link timestamps on open. Resolve fresh streams on reopen or retry; never persist signed URLs/headers. Show saved links for manual reopening after restart; startup still restores the last local file without fetching YouTube.
- Before loading a resolved stream, set mpv's force-media-title to the extracted title so IINA and mpv show the video name instead of the signed stream address. Pass it as a literal IPC string, not a window-title expression. Clear the override when loading a local file so the previous stream title cannot carry over.
- Explicit background mode first verifies the native tray, then hides the retained empty main window and disposes the app WebView/context. Retain the empty window because disposing the last native window exits WebviewJS. Tray Open and incoming OS files recreate one interface using the persistent profile. Tray play/pause and time jumps use the same commands and configured intervals. Close and tray Quit stop the owned playback, speech, sources, and host. Video uses mpv's separate native window. Global shortcuts and OS media-session adapters remain pending.
- Defer native tray menu actions with `setImmediate` before creating contexts, recreating the window, or quitting. WebviewJS dispatches these callbacks while `pumpEvents` holds the native Application borrow. Check disposal again after deferral; catch a failed Open once without a recursive retry.
- Save normal window position in physical coordinates and inner size in logical units in private `window.json`; save maximized state separately. Defer and debounce move/resize reads outside native events. Flush before hiding and exit. Hidden, minimized, and fullscreen geometry must not replace normal bounds. Restore before showing, clamp to an available monitor, and keep the window off the always-on-top and all-workspace modes. Do not force focus at startup; an explicit tray Open or incoming file can focus it.
- Geometry does not identify a macOS Space. WebviewJS has no public Space-selection API in the current version. Keep Space assignment and Mission Control preferences under user control; do not change global macOS settings or use private workspace APIs. A debug Bun process does not have the packaged Shravanam application's identity for per-app Dock assignments.
- Keep native decorations disabled. The HTML startup header provides movement and close controls before Svelte loads and after startup failure.
- The current WebView directory is persistent. Do not clear it or assume it holds only reproducible cache.
- Native source configuration does not establish tested platform support.

## Verification

- `tests/player-settings.test.js` checks local executable-path persistence, reset, archive exclusion, invalid paths, failed-write recovery, and explicit-path failure without fallback.
- `bun test` checks late EOF events, storage recovery, source-window isolation, authenticated source commands, userscript matching/timing/persistence, download paths and lifecycle, and local restoration of source progress. Native browser/site behavior and real downloads remain separate checks.
- `tests/window-state.test.js` checks saved geometry, monitor changes, scale factors, and hidden/maximized states. `tests/webdav-host.test.js` uses an isolated loopback server for native synchronization requests, streamed bodies, conflicts, and responsive controls during preview. A sandbox that blocks listening needs a test run with loopback access. This is not verification of a real WebDAV provider.
- Run desktop builds and native checks only when requested.
